# SERVER_SETUP – חיבור האפליקציה לשרת (Supabase), צעד אחר צעד

> **למי:** לבעלים של האפליקציה, בלי רקע טכני. כל צעד קצר, והוא אומר מה לבדוק כדי לדעת שהצליח.
> **עלות:** 0 ₪. החבילה החינמית של Supabase לא מבקשת כרטיס אשראי (לוודא בהרשמה; אם מבקשים – לעצור ולהגיד לי).
> **זמן:** כ-15 דקות.

## מה זה נותן
- הנתונים נשמרים בחשבון ולא רק בדפדפן: אפשר להתחבר מהטלפון ומהמחשב ולראות אותו דבר.
- כניסה בלי סיסמה: מקבלים קוד (6 עד 10 ספרות, לפי הגדרת הפרויקט) באימייל.
- כל משתמש רואה רק את הנתונים של עצמו (הכלל הזה נאכף בבסיס הנתונים עצמו, ונבדק אוטומטית).

## צעד 1 – פתיחת פרויקט
1. נכנסים ל-<https://supabase.com> ופותחים חשבון (אפשר עם GitHub או אימייל).
2. **New project**. שם: `diet-plan`. אזור (Region): **Frankfurt** (הכי קרוב לישראל).
3. **Database password**: ללחוץ Generate ולשמור אותה במקום בטוח (מנהל סיסמאות). **אותה לא שולחים לאף אחד, גם לא לי** – היא לא נחוצה לאפליקציה.
4. מחכים כדקה-שתיים עד שהפרויקט מוכן.

## צעד 2 – יצירת הטבלאות
1. בתפריט הצדדי: **SQL Editor** → **New query**.
2. פותחים את הקובץ [`supabase/migrations/20261002000000_init.sql`](../supabase/migrations/20261002000000_init.sql), מעתיקים את **כל** התוכן, מדביקים בחלון, ולוחצים **Run**.
3. אמור להופיע `Success. No rows returned`. (אם יש שגיאה – מצלמים מסך ושולחים לי.)
4. לבדיקה: **Table Editor** – צריכות להופיע 6 טבלאות: `profiles`, `target_plans`, `weight_entries`, `meals`, `favorites`, `audit_events`.

## צעד 3 – שהאימייל יישלח קוד ולא קישור (חשוב!)
בברירת מחדל Supabase שולח **קישור**, והאפליקציה מצפה ל**קוד**. את תבנית המייל **אי אפשר לערוך** כל עוד Supabase שולח את המיילים בעצמו (מופיעה הודעה "Set up custom SMTP to edit templates"), ולכן קודם מחברים שליחת מיילים משלנו:

**3א. סיסמת אפליקציה ב-Gmail** (בלי לפתוח שום חשבון חדש):
1. <https://myaccount.google.com/apppasswords> (דורש שאימות דו-שלבי בחשבון Google מופעל).
2. שם: `יומן תזונה` → **Create** → מועתקת סיסמה בת 16 אותיות. היא תשמש רק לשליחת המיילים, אפשר למחוק אותה בכל רגע.

**3ב. חיבור ב-Supabase:** **Authentication → Emails → SMTP Settings** (כפתור **Set up SMTP**):
- Sender email: כתובת ה-Gmail · Sender name: `יומן תזונה`
- Host: `smtp.gmail.com` · Port: `587` (אם נכשל: `465`)
- Username: כתובת ה-Gmail המלאה · Password: סיסמת האפליקציה (3א)
- **Save**. את הסיסמה הזו מדביקים רק שם – לא שולחים לאף אחד.

**3ג. תבנית המייל:** **Authentication → Emails → Magic link or OTP** → בגוף (**Source**) מוחקים הכול ומדביקים:
```html
<p>קוד הכניסה ליומן התזונה שלך:</p>
<h2>{{ .Token }}</h2>
```
ולוחצים **Save**.

## צעד 4 – להעתיק לי שני ערכים (בטוחים לשיתוף)
**Settings → API Keys** (או כפתור **Connect** בראש הדף):
- **Project URL** – נראה כך: `https://abcdefgh.supabase.co`
- **Publishable key** (מתחיל ב-`sb_publishable_`) – או בשם הישן **anon public**.

> ✅ מותר לשלוח לי: ה-URL והמפתח ה-**Publishable/anon**. הם גלויים לכל מי שפותח את האתר, וההגנה על הנתונים באה מכללי הגישה בבסיס הנתונים.
> ⛔ **לא** לשלוח: **Secret key** / **service_role** / סיסמת בסיס הנתונים.

## צעד 5 – חיבור (אני עושה)
אני שם את שני הערכים בקובץ `.env` מקומי (הוא לא נשמר ב-Git) ומריץ את האפליקציה. מי שרוצה לעשות לבד: להעתיק את `.env.example` ל-`.env`, למלא את `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_ANON_KEY`, ולהריץ `npm run dev`.

## צעד 6 – בדיקה ראשונה (ביחד)
1. פותחים את האפליקציה → מסך התחברות → מקלידים אימייל → "שליחת קוד".
2. הקוד מגיע לאימייל (עד דקה) → מקלידים → נכנסים → עוברים את ההרשמה (גיל, משקל, יעד).
3. מוסיפים ארוחה. פותחים את האתר בדפדפן אחר/בטלפון, מתחברים עם אותו אימייל – הארוחה שם.

## מה כדאי לדעת
- **מי יכול לקבל קוד באימייל?** עם שליחה דרך Gmail אפשר לשלוח לכל כתובת (עד כמה מאות הודעות ביום), גם למשתמשים נוספים. ההודעות יוצאות מכתובת ה-Gmail שלך.
- **לחסום הרשמות של זרים:** אחרי שנכנסת בפעם הראשונה אפשר לכבות **Authentication → Sign In / Providers → "Allow new users to sign up"**. אז רק החשבון שכבר קיים יכול להיכנס.
- **ריחוק:** פרויקט חינמי שלא נעשה בו שימוש כשבוע **מושהה אוטומטית**; מחדשים בלחיצה אחת בדף הפרויקט ואף נתון לא נמחק.
- **גיבוי:** בהגדרות האפליקציה יש "הורדת הנתונים שלי (JSON)". בחבילה החינמית אין גיבוי אוטומטי של Supabase – כדאי להוריד קובץ מדי פעם.
- **מחיקה:** בהגדרות יש "מחיקת כל הנתונים" (נשאר חשבון ריק) ו"מחיקת החשבון" (הכול נמחק לצמיתות).

## בדיקה ידנית מול הפרויקט האמיתי (לפני שמסתמכים על זה)
הבדיקות האוטומטיות מריצות את אותו SQL על בסיס נתונים אמיתי (PGlite) ואת האפליקציה מול שרת מדומה בפורמט של Supabase. את מה שנשאר רק הפרויקט האמיתי יכול להוכיח:
- [ ] קוד מגיע באימייל, והכניסה עובדת.
- [ ] הרשמה מלאה נשמרת (פרופיל + יעד + שקילה), ורענון הדף מחזיר אותך ישר לאפליקציה.
- [ ] ארוחה שנוספה בטלפון מופיעה במחשב אחרי רענון.
- [ ] משתמש שני (אימייל אחר, אם אפשר) **לא** רואה את הנתונים שלך.
- [ ] "מחיקת החשבון" באמת מוחקת (בדיקה בטבלאות ב-Table Editor).
